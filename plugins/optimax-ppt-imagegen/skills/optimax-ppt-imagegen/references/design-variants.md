# Three-proposal selection strategy

Select three information architectures that fit the content. The proposal roles are stable, but the layouts are not fixed.

## Content-to-layout matrix

| Content archetype | A — clarity-first | B — executive-story | C — system-view |
| --- | --- | --- | --- |
| Sequential process or implementation | Stage cards or linear pipeline | Swimlane or four-phase methodology | Feedback loop or operating cycle |
| Product or platform architecture | Layered stack | Input–engine–output | Hub-and-spoke or capability network |
| Decision, risk, or operations | Signal–verify–decide–act | Decision tree or impact pathway | Control tower, dashboard, or closed loop |
| Product value or solution story | Problem–solution–value | Capability-to-outcome map | User-role ecosystem or value flywheel |
| Roadmap or transformation | Timeline or now–next–later | Maturity ladder | Workstream portfolio or dependency map |
| Comparison or selection | Side-by-side comparison | Weighted decision matrix | Before–after transformation map |
| Operating model or organization | Role swimlane | Governance layers | Cadence loop or responsibility network |
| Data, metrics, or performance | KPI dashboard | Driver tree | Insight-to-action loop |

## Distinction test

Before generation, describe each proposal in one line. Reject and replace an option when any two share all three of these:

- the same outer silhouette;
- the same module hierarchy;
- the same arrow or reading path.

Changing only color, icons, card corners, or module order does not create a distinct proposal.

## Copy adaptation

- Preserve source facts, named products, metrics, and commitments.
- Unless the user requires verbatim text, replace implementation jargon or literal translations with natural audience-facing Chinese.
- Prefer short action or outcome labels: `信息汇集`, `事实核验`, `管理研判`, `知识更新`, `待办同步`, `简报输出`.
- Avoid unexplained labels such as `更新门`, `待办门`, `写后验证`, `双写一致`, or `优先级抑制` in executive slides.
- Lock the rewritten labels before ImageGen and require verbatim rendering in every proposal.

## Reference asset routing

- `assets/stage-rollout.png`: stages, roadmaps, maturity, rollout, comparison.
- `assets/problem-solution-value.png`: pain-to-value, solution narrative, capability-to-outcome.
- `assets/operations-pipeline.png`: signal processing, risk operations, control tower, input–output.
- `assets/agent-orchestration.png`: hub-and-spoke, Agent collaboration, governance network, operating model.

Different proposals may use different references. Keep palette, card language, icon weight, spacing, and typography consistent across the set.
